# 与原版逐项对照

对照的是上游 [Eidolon-SC](https://github.com/Sallyn0225/eidolon-sc) 的后端（`backend/src/eidolon/`，107 个模块）与前端（`frontend/src/`）。分三类：**对上了**、**故意不一样**（并写为什么）、**没移植**（并写缺什么）。

判断标准是「用户看得见的行为」，不是代码长得像不像。

## 一、对上了

| 原版 | 这里 | 说明 |
|---|---|---|
| `reply_format.py` | `core/protocol/reply.py` | `<ja>/<zh>` 分段、流式增量、字幕与原文各自成段 |
| `delivery_cues.py`（ADR-0007） | `core/protocol/cues.py` | 语气提示**存原样、读时剥**；行首空格会被吃掉、删提示后两侧空格保留，这两处反直觉的行为一并照抄 |
| `engine.py` 的提示词（ADR-0020） | `core/prompt.py` | 四段结构与缓存断点；人设 + 世界书 → 制作人 → 历史 → 这一轮 |
| `engine.chat_history` | `core/prompt.py:trim_history` | 历史涨到 1.5 倍再一次性裁回，保证前缀稳定 |
| `judge.py` | `core/judge.py` | 多个问题合一次请求；判官失败即当作没答，不猜 |
| `affinity.py` | `plugins/affinity.py` | 0–100 浮点、初始 50、档位 0/20/40/65/85、五级步长 −5/−2/0/+1/+2、越线 −10、日上限 6、恢复 10/天、冷却 0→10、礼物 +3/+5/+7（喜欢 +3、冷却内最多 +3）、重置卡只拉回信任以下 |
| `affinity.py` 的档位提示词 | 同上 | `_TIER_PROMPTS` / `_FONDNESS` / `_WHATEVER_THE_TIER` 逐字照抄，页面上不显示分数 |
| `memory.py`（ADR-0002） | `plugins/memory.py` | 制作人的记忆**所有角色共用**；不是对她说的事，要按「听 X 说」转述 |
| `memory.py`（ADR-0014） | 同上 | 新记忆可以取代旧记忆；被取代的不再被想起、但还在列表里；删掉取代它的，旧的就恢复 |
| `memory.py` 的抽取提示词 | 同上 | 「只记过后仍有意义的事」「相对时间换算成日期」「只输出 JSON」等逐字照抄；单次最多 5 条、单条 200 字 |
| `gift_catalog.py` | `plugins/gifts.py` | `gifts.toml` 的校验（标识/类别/稀有度/下架、每档至少一件没下架）；写错就不开礼物页 |
| `gifts.py` | 同上 | 每天 1 次、最多攒 7 次、1%/69%/25%/5%、背包叠加、送礼、重置卡 |
| `stats.py` | `app.py:stats` | 形状一致：认识天数、连续来访（今天没来就从昨天数）、24 小时分布、52 周热力图、按档位分组、按跨度变化的回合数与送礼 |
| `usage.py` | `plugins/quota.py` | 滑动一小时、成功才结账、`retry_after` 是最早那次到期的时间 |
| `service_status.py` | `plugins/status.py` | 15 分钟窗口内的成败 |
| `data_package.py` | `app.py:export/import` | 对话 + 记忆 + 档案的往返；角色不在本部署的对话跳过 |
| `producer.py` | `plugins/profile.py` | 称呼、性别、生日、时区 |
| `characters.py` | `plugins/characters.py` | `characters.toml` 的字段（含 `liked_gifts`）；没有 toml 时每个 `*.md` 是一个角色 |
| `facts.py` + `embedded_texts.py`（角色的资料） | `plugins/recall.py` | 同一份 `facts/<id>.md` 有两种用法：**数据版**整份进人设、跟人设一起缓存；**向量版**按标题切段、嵌入后每轮只带最近的几段。`SCCORE_RECALL_GATE=judge` 复刻上游「这一轮要不要查资料」的门控（上游用 JEV），失败时照查 |
| `embedding.py`（ADR-0005） | 同上 | 只留 OpenAI 兼容的 `/embeddings` 一条路（硅基流动 Qwen3-Embedding、OpenAI、Jina、本地 Ollama 都行）；向量按「角色 + 模型 + 原文」存，换模型等于换一套，改过的段落只重嵌那几段 |
| 前端的九类设置、列表排序、历史对话面板 | `web/assets/app.js` | DOM 与 class 照抄，连「她结束了对话」的文案位置都留着 |

## 二、故意不一样

| 原版 | 这里 | 为什么 |
|---|---|---|
| 记忆用**向量检索**：嵌入当轮问题，取最近 12 条候选，再用重排模型挑 3 条 | 记忆没有嵌入与重排：提示词里放**最近 8 条**仍然成立的记忆，抽取时把最近 20 条给模型看（角色的**资料**另有向量版，见上表） | 记忆每轮都变、条数又多，嵌入是另一家服务与另一把 key；用「最近」换掉「最相关」，是零依赖这个硬约束下最诚实的做法。资料的向量版做成了可选开关，因为它只在部署者愿意多配一个服务时才需要 |
| 记忆在**后台任务**里写，下一轮开头等它一会儿 | 后台**线程**写，下一轮 / 列表 / 删除最多等 5 秒 | 同样的语义（不让写记忆拖慢回复），实现换了：内核是同步 HTTP + SSE，没有常驻事件循环 |
| 判官用**结构化输出**拿每一级的概率，再按阈值判 | 要求模型直接输出 JSON：等级 0–4 的整数 + 两个布尔 | 一边是厂商特有的采样参数，一边是一个到处都能用的 JSON 约定；拿不准时取「没有影响」 |
| 好感度到顶时她会**结束这段对话**，页面上出现结束卡 | 只做冷却：下一轮直接被拒，`retry_after` 告诉她什么时候回来 | 「结束对话」是一套独立的状态机（结束原因、结束卡、再来一段），够一个插件自己去做 |
| 礼物是**对话事件**，时间线上有「你送给她一份蛋糕」这一行 | 礼物记在礼物自己的表里，只影响好感度与统计 | 时间线要内核认第三种消息（既不是你也不是她），这套内核没有为它开缝 |
| 自带密钥时**整个回合**都用你的 key（对话、判官、记忆） | 只有**对话**用你的 key，判官与记忆抽取仍用部署的 key | 判官不是每轮新建的，它是宿主的一部分；把它做成临时的要动宿主 |
| 记忆 ID 是自增整数，数据包里用它表示取代关系 | 一致 | — |

## 三、没移植

| 原版 | 缺什么 | 大概要补什么 |
|---|---|---|
| **语音通话** `call.py`（1769 行） | 一条实时语音链路：麦克风 → STT → LLM → TTS → 扬声器，WebRTC 信令、打断、挂断条件、通话记录与统计 | WebRTC 运行库（Pipecat 一类）与 STUN/TURN；与「只用标准库」直接冲突，属于另一个项目 |
| **剧情库与重排** `corpus.py`、`story_import.py`、`reembed.py`、`rerank.py`、`recall_story` 工具 | 30MB 剧情 CSV（无许可证，不适合随仓库分发）的导入与切分、重排服务、以及模型主动查剧情的工具调用协议 | 资料检索已经由 `plugins/recall.py` 顶上，不需要剧情库也能用；真要搬剧情库，得先解决数据许可，再补重排（一条 `/rerank` 调用）与工具调用 |
| **世界书** `world.py`、`world_sync.py` | `world.json`（1.4MB）里的组合、剧情时间线与设定修正 | 组合与顺序已经写进 `plugins/characters.py` 的一张表；剧情时间线属于剧情库的一部分，跟着上一条 |
| **公告** `announcements*.py` | 后台写公告、置顶、发布；前端铃铛 | 单用户部署没有「发布者」；铃铛现在是空态 |
| **搭话** `reach_outs.py` | 定时任务判断「该主动找他了」，生成一条消息推到列表 | 需要常驻调度与未读状态；前端的开关已经按「部署者没开就不显示」处理 |
| **SCSP 生图** `image_generation.py`、`photo_prompt.py`、`photo_judge.py` | 她会「拍」一张照片发过来：提示词、图像服务、失败兜底 | 一家图像服务 + 一套提示词工程；本版只做**上传**图片 |
| **账号 / 后台 / 计费** `accounts.py`、`sessions.py`、`admin_*.py`、`billing.py`、`prices.py`、`sponsor.py` | 多用户、登录方式、管理员、限额后台、赞助 | 这个仓库明确是单用户本地部署：一个人、一份库、自己的 key |
| **自带密钥的试调** `own_keys.py` | 保存前试调一次、按服务校验、豁免计数 | 现在只做「带上就生效」：key 对不对要等第一句话；豁免计数已经做了 |
| **落地页** `greetings.py` + `frontend` 的 landing | 她主动打来的演示电话、招呼语音、字体子集 | 那是展示页，不是应用本身 |

## 四、这一版做了什么

如果只看「比上一版多了什么」：

1. **记忆**：跨角色共享 + 转述口吻 + 被取代（ADR-0002 / ADR-0014），抽取从「一问一句」换成上游那套看历史、看回复、看已知记忆的 JSON 抽取。
2. **好感度**：数值、档位、日上限、恢复、冷却、越线、礼物加成全部对齐上游；档位提示词逐字照抄；冷却时她真的不接话。
3. **礼物**：目录、抽奖、背包、送礼、重置卡、统计，界面从「暂时没有开放」变成一个能用的礼物页。
4. **自带密钥**：设置里填的 key 真的用在那一轮对话上，并且不计入每小时限额。
5. **统计**：送礼进热力图与「送出的礼物」。
6. **角色的资料**：数据版（整份进人设，缓存）与向量版（切段嵌入、按轮取几段）一个开关切换，向量版可再开判断模型门控。

对照的结论是可复核的：`tests/` 里为每一条对齐的语义留了测试，名字就是那句话（例如 `test_deleting_what_superseded_it_brings_it_back`）。
