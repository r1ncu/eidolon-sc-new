# 部署者要补的数据

> **这个仓库不含任何角色。** 它有内核、通道、格式说明和自造示例，没有人设、头像、
> 剧情台词，也没有任何真实号码。`git clone` 之后服务能起、接口能通、网页能打开，
> 但角色列表是空的，QQ 通道没有人格可演——**不补数据不算部署完成**。
>
> 本文是「哪些地方要补」的单一真相：逐项列出代码会去读、仓库却不带的文件。
> 格式怎么写见 [characters/README.md](../characters/README.md)、
> [world/README.md](../characters/world/README.md) 和
> [04 · 自定义角色](qq-channel/04-自定义角色.md)；
> 架构上为什么这样分层见 [architecture.md](architecture.md) §1.4 / §3。

所有路径相对仓库根目录，`<id>` 是你在 `characters.toml` 里给角色的标识。
**先读 `characters/packs/<id>/`，再退回旧的扁平名**（`world/<id>-qq.md` 那一套）；
旧路径仍能读，但新写的文件一律放包里。

## 1. 一页纸清单

| 档 | 路径 | 谁读它 | 不补会怎样 |
|---|---|---|---|
| **必需** | `characters/characters.toml` | `plugins/characters.py` | 没有名册时，目录里每个 `*.md` 被当成一个角色（文件名即 id）；一个都没有就是空列表 |
| **必需** | `characters/packs/<id>/persona.md` | 人设 → `persona` 槽 | 她没有「我是谁」，会用世界知识现编，越聊越像通用助手 |
| **必需** | `characters/packs/<id>/voice/qq.md` | `channels/presence.py` | 群聊退成中性语气（礼貌的陌生人） |
| **必需** | `characters/packs/<id>/voice/dm.md` | 同上 | 私聊退成中性语气 |
| 表现 | `packs/<id>/names.toml` | `channels/qq.py` | 说名字不算叫她、【名字】提示段空转、指令里叫不出她的名字 |
| 表现 | `packs/<id>/voice/stage.toml` | `channels/qq.py` | 熟悉度阶梯没有档位，句数不随熟人变化 |
| 表现 | `packs/<id>/voice/tiers.toml` | `channels/presence.py` | 好感五档没有各自声线，只靠人设自己变 |
| 表现 | `packs/<id>/voice/qzone.md` | `channels/qzone.py` | **不发说说**（`maybe()` 直接拒发，不是退回通用文案） |
| 表现 | `packs/<id>/voice/refusals.toml` | `channels/qq.py` | 拒绝台词用中性默认（礼貌、无个性）。这里每句都必须是中文 |
| 表现 | `packs/<id>/voice/interests.md` | `channels/interests.py` | 什么都接一点，显得没有偏好 |
| 表现 | `packs/<id>/voice/night.toml` | `channels/qq.py` | 按通道默认 23:00 睡 / 9:00 醒；幼年版熬到十一点没人知道为什么 |
| 表现 | `packs/<id>/view.md` `world.md` | `channels/presence.py` | 只有事实没有视角，她像在念维基 |
| 表现 | `packs/<id>/facts.md` | `plugins/recall.py` | 问深了答不出来（`SCCORE_RECALL=whole` 时整份进提示词） |
| 表现 | `packs/<id>/relations.toml` | `channels/world.py` | 提到同行时没有亲疏信息 |
| 表现 | `packs/<id>/stories.toml` + `facts-stories/` | `plugins/stories.py` | 话题命中时没有剧情原文可注入 |
| 表现 | `characters/world/{work,office,meta}.md`、`world/idols/` | `channels/world.py` | 共享层空：名单、作品常识都没有 |
| 可选 | `packs/<id>/voice/tease.toml` + `tease.md` | `plugins/tease.py` | 这个机制当不存在（`{{extra}}` 占位会被收掉） |
| 可选 | `packs/<id>/assets/{avatar,scsp,background,call-background}.*` | `serve.py` / 网页 | 头像与壁纸退成印象色，不报错 |
| 可选 | `characters/works/<作品id>.toml`、`units.toml`、`gifts.toml` | 各插件 | 没有分组 / 作品归属 / 礼物目录，功能安静地不出现 |
| **自带** | `characters/calendar.toml` | `channels/calendar.py` | 仓库带了日本祝日表（公开数据，覆盖 2026–2027），每年更新一次即可 |

「不补会怎样」一栏都是**中性退路**，不是报错：少一份文件最多是少一层表现，
不会让服务起不来。这也是最容易误会的地方——**能跑 ≠ 演对了**。

## 2. 最小可跑集合

```bash
cp characters/characters.example.toml characters/characters.toml
mkdir -p characters/packs/<id>/voice
# 写这四份：characters.toml 里登记 id；persona.md；voice/qq.md；voice/dm.md
python tools/check_packs.py <id>     # 必需项齐不齐
```

`characters.toml` 里 `id` / `sheet`（或包里的 `persona.md`）/ `.env` 的 `QQ_CHARACTER`
三处要一致。只跑网页时 `QQ_CHARACTER` 可以不管。

再往下按你要的通道补：群聊至少 `names.toml` + `voice/stage.toml`，
想让好感影响语气补 `voice/tiers.toml`，开空间就补 `voice/qzone.md`，
在乎作息补 `voice/night.toml`。

## 3. 格式样板在哪

| 要写什么 | 看哪份 |
|---|---|
| 名册字段（id / name / adult / plove / heavy / derived_from…） | `characters/characters.example.toml` |
| 组合表、作品表 | `characters/units.example.toml`、`characters/work.example.toml` |
| 群聊 / 私聊语域、`{{extra}}` 占位 | `characters/world/README.md`；`docs/qq-channel/templates/world/example-{qq,dm}.md` |
| 措辞表、拒绝台词、插话清单 | `docs/qq-channel/templates/world/example-{stage,refusals,interests}.toml/md` |
| 一步步写完整包 | `docs/qq-channel/04-自定义角色.md` |
| 包结构、继承白名单、每项文件的旧路径 | `plugins/packs.py` 的 `_LAYOUT`（唯一真相） |

示例里的人名、id 都是自造的，不是任何真实角色；照格式改，不要照内容抄。

## 4. 派生角色（`derived_from`）额外要补的

`packs/<id>_young/`、`packs/<id>_if/` 这类「同一个人的另一个形态」：

- **必须**自己写 `voice/night.toml`（小孩不能按成年那位的钟点睡），`check_packs.py` 会查；
- 记忆、睡眠账本按各自的 id 分开存，**好感记在本体名下**（`Affinity(root=)`，
  本体 / 幼年 / if 线共用一行；群聊、私聊、网页仍各算各的），
  升级旧库时用 `python tools/fold_affinity.py --db <库> --characters characters --apply` 折平；
- `tease` / `tiers` / `stage` / `stories` / 头像**不继承**，记忆永不继承；
  能借的是 `_LAYOUT` 里标了 `inheritable=True` 的那几项。

## 5. 自检

```bash
python tools/check_packs.py            # 每个包读不读得通、必需项齐不齐、TOML 能不能解析
python tools/check_roster.py           # 名册字段有没有漏 / 自相矛盾
python -m unittest discover -s tests -t .   # 干净 checkout 会因缺角色数据跳过/失败少数用例，属既有情况
```

网页端「设置 → 世界观」会逐个显示包在哪、必填缺哪几份、哪些还在旧路径；
启动日志那行 `角色包 <id> / 在 packs/<id> / 旧路径：… / 未写：…`
也能一眼看出「她读的是不是你以为的那份」。

## 6. 不要放进来

- 官方立绘、语音、剧情文本、歌曲信息，以及任何他人的角色设定；
- 你自己的 `characters/memory/`、`.env`、`*.db`、日志、表情包缓存；
- 别人的 QQ 号、群号、聊天记录。

后两类由 `.gitignore` 挡着，但它只是最后一道门。前一类**没有任何机制能替你挡**：
角色内容由部署者自己准备、自己负责，仓库不分发也不代管。

## 7. 三个常见误会

1. **「代码里写死了一个角色，改掉就行」** —— 没有。所有默认值都是中性占位，
   缺文件时退回的是机制话术，不会悄悄落到某个具体角色身上。
2. **「`packs/` 建了目录就算有角色」** —— 要 `persona` / `qq` / `dm` 三份都在包里，
   `check_packs.py` 才判 `OK`；其余项允许继承或缺失。
3. **「旧路径已经不能用了」** —— 还能用，解析顺序是先包后旧路径。
   但同一个 kind 两边都写时以包为准，排查「改了没生效」先看这里。
