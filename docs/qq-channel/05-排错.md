# 05 · 排错

排错的顺序永远是：**先问它自己，再猜。** 这个通道会主动说原因，两句就够：

```bash
curl -s localhost:8100/api/qq/status | python -m json.tool
# 日志里那行 "QQ 通道..." 就是它的自述
```

---

## 一、启动就不对

### 日志里没有 "QQ 通道" 这一行

三种可能，从便宜到贵：

1. `.env` 里没有 `QQ_ENABLED=1`（`0`/空都是关）。
2. `channels/` 不在内核根目录 → `App` 里 `_qq_plugin` 导入失败，静默跳过。
   验证：`python -c "import channels.plugin_qq; print('ok')"`（在内核目录下跑）。
3. 内核版本太旧，没有 `Plugin.start` → 永远不会被启动，也不报错。见 [06](06-内核补丁.md)。

### `QQ 通道没有启动：<原因>`

那半句就是答案，逐条对：

| 它说的 | 你要做的 |
|---|---|
| `QQ_ENABLED 不是 1` | 设成 `1` |
| `QQ_GROUP_IDS 和 QQ_PRIVATE 都是空的` | 填群号，或者 `QQ_PRIVATE=1` |
| `QQ_SELF_ID 是空的` | 填机器人自己的 QQ 号（不是你的号） |
| `QQ_CHARACTER 是空的` | 填角色 id，要和 `characters.toml` 里的一致 |
| `QQ_ONEBOT_WS 是空的` | 填 `ws://127.0.0.1:3001` |

### 起来了，但 `connected: false`

NapCat 那半边的问题，不是插件。按顺序查：

1. NapCat 容器/进程活着吗？`docker ps | grep napcat`
2. 端口开着吗？`curl -sv http://127.0.0.1:3001` —— `Connection refused` = 没开
3. 开的是"WebSocket **服务器**"吗？（WebUI 登录 ≠ 开了 OneBot，是两页）
4. token 一致吗？`last_error` 里通常直接写着 `401` / `403` / `handshake`
5. 容器里地址写对了吗？同一 compose 网络用服务名 `ws://napcat:3001`，不是 `127.0.0.1`

详见 [03-NapCat](03-NapCat.md)。

## 二、连上了，但她不回复

按这条链子一个个排除，**从上往下**：

| 环节 | 怎么查 |
|---|---|
| 消息到了吗 | `status` 的 `events` 在涨吗？不涨 = 线断了 |
| 群号对吗 | `status` 的 `groups` 里有没有这个群 |
| 是不是在 @ 她 | 只有 @ 或叫名字才会答。`@` 要真的 at，不是打文字 |
| 是不是同一个人在刷 | 同一人 20 秒内只答一次（`QQ_MEMBER_COOLDOWN`） |
| 是不是被静音了 | 发 `/解除`；`status` 里 `people` 是认识的人数 |
| 是不是限额用完了 | 页面 `/api/state` 看剩余轮数；`QQ_*` 里没有，是内核的 `SCCORE_TURNS_PER_HOUR` |
| 是不是太长了 | 超过长度上限会被拒，她会说一句"太长了" |
| 模型是不是挂了 | `status` 的 `last_error`、内核日志里的 `TurnFailed` |

### 私聊不回

私聊是白名单制，**默认全关**：

```ini
QQ_PRIVATE=1
QQ_PRIVATE_IDS=你的QQ号      # 留空则沿用 QQ_OWNER_IDS
```

另外私聊里她可能"正在生气/冷静中"（`cooling`），那是好感度机制，不是 bug。

## 三、回得不对

### 不像那个角色

按影响从大到小：

1. **`QQ_CHARACTER` 指错了** —— 用的是另一个人的 sheet。日志那行写着角色 id，对一下。
2. **缺 `-qq.md`** —— 她只在用人设裸聊，没有"群里该怎么说话"的规则。
3. **人设里全是形容词** —— 模型对"温柔""毒舌"的想象和你的不一样。改成三句原话样本。
4. **判官把她判低了** —— 群里连续被同一个人追问，判官会扣好感，语气变冷。设 `QQ_OWNER_AFFINITY` 给主人抬地板。

### 群聊和私聊串味

不该发生：`-qq.md` 和 `-dm.md` 是两份文件，而且群聊规则进的是 `TURN` 槽、
私聊的场景段进的是 `PERSONA` 槽。如果确实串了，检查是不是在 `-dm.md` 里写了"群里"相关的话
（有些句子会被人设记住并带到群里）。

### 记忆文件里的内容串到群里

记忆是按场次分开的：`dm-<QQ号>.md` 只进私聊，`group-<群号>.md` 只进那个群。
如果串了，看 `QQ_DIGEST_PROMPT` 和日志里 `qq: ... 的记忆写好了 → <路径>`，确认写的是哪个文件。

### 私聊里说过的事出现在群里

记忆是**按场合分开的**：私聊里记下的只会在私聊里被想起，群里记下的只会在群里被想起，
群聊里就算和制作人本人说话，她也不会提私聊的事。两边各有各的那一份，互不串。

设置页「记忆」里每条都有一个来源标签：**私聊 / 群聊 / 网页**。看到某条被归错了地方：

```bash
# 看这个人的记忆都在哪个场合（u 是他的 user id）
curl -s "localhost:8100/api/memory?u=<user>&s=dm"   | python -m json.tool
curl -s "localhost:8100/api/memory?u=<user>&s=group" | python -m json.tool
```

改一条的场合（数据库在容器里是 `/data/scbot.db`）：

```sql
UPDATE memories SET surface = 'group' WHERE id = 42;
```

升级上来的老记忆没有场合标签，第一次读取时会按「有私聊记录的 → 私聊、在群里说过话的 →
群聊、剩下的 → 网页」归一次档。**猜错的方向是往私的那一边猜**：一条记忆被归到私聊，
最多是群里想不起来；被归到群里，就是当着五十个人说。

### 插话太多 / 从来插话

先看两个数字，别猜：

```bash
curl -s localhost:8100/api/qq/status | python -c "import json,sys; d=json.load(sys.stdin); print(d['ambient_today'], '/', d['ambient_daily'])"
```

`ambient_today` 是今天说过几次。它一天最多涨到 `ambient_daily`。

| 现象 | 调 |
|---|---|
| 太吵 | `QQ_AMBIENT_DAILY` 调小（10 是「一天十次上下」） |
| 从不插话（`ambient_today` 一直是 0） | 按顺序查：`QQ_AMBIENT=1`？`QQ_AMBIENT_P` 是不是太小（0.05 = 二十条才看一次）？`-interests.md` 里的「不接」是不是写得太宽（她真的在按它闭嘴）？日志里有没有 `判断要不要插话失败`（模型挂了 → 她一律不说） |
| 插话都在接同一句感想、没有自己的想法 | `QQ_AMBIENT_OWN_P` 提到 0.35 |
| 总在回最后一句，不回更早的问题 | 正常优先最新；**判断的人只看见 `QQ_AMBIENT_HEARD` 行**，调大就看得更远 |
| 半夜说话 | `QQ_AMBIENT_IDLE` 只在 9:00–23:00 生效；若是被 @ 回复，那是正常的 |

日志里每插一次都有一行：

```
qq: 插了一句（今天的第 3 次，接 某某：…… / 接得上）
```

斜杠后面是判断的理由。觉得她选得不对，先看这一行，再看 `-interests.md`。

### 每次回复都很长 / 很短

长度规则在 `-qq.md` 的 `【长度】` 和 `-dm.md` 的 `【长度】` 里。改文件、`/重载`，不用重启。

## 四、表情

| 现象 | 原因 |
|---|---|
| `/表情 同步` 说拿到 0 张 | 这个号没收藏过表情，或者 NapCat 版本不支持 `fetch_custom_face` |
| 收不到群友发的表情 | `QQ_STICKERS=1`；只收**图片类**的表情（贴图/GIF），不支持系统表情 |
| 想发但没得发 | 先发一次那张表情进群（或 `/表情 同步`），再用 `/表情标 标签` 给它命名 |
| 群友不能用 `/表情` | `QQ_STICKERS_PUBLIC=1`（唯一对群友开放的指令，每人 15 秒一次） |

表情文件存在 `QQ_STICKER_DIR`（默认数据卷 `media/stickers`）。**容器重建后这个目录要在卷里**，
否则每次都从零开始。

## 五、记忆文件没生成

先确认开关：`QQ_DIGEST=1`，并且距上次整理超过 `QQ_DIGEST_DM_DAYS`（默认 3 天）。
**少于 4 条新消息不写**——这是省钱的，不是坏了。第一次启动会立刻写一份（90 秒后检查）。

文件在 `characters/memory/`：

```
dm-<QQ号>.md
group-<群号>.md
```

### 报 `PermissionError`

容器里跑的用户（通常 uid 10001）对挂载出来的目录没有写权限。宿主机上：

```bash
mkdir -p characters/memory
sudo chown -R 10001:999 characters/memory
sudo chmod 2777 characters/memory
```

`2777` 里的 `2` 是 setgid：新写的文件继承目录的组，下次不用再改。**重装容器后要重做一次**，
因为宿主目录的属主不会跟着镜像走。

### 文件是空的 / 只有标题

模型那次给了空回答，日志里有一行 `qq: dm 的记忆这次没写成（模型给了空回答）`。
通常是模型在长提示词上摆烂，重试一次；持续这样就把 `QQ_DIGEST_DM_DAYS` 调大、
一次喂更少的话。

## 六、图片

- 群里发图她会看，前提是**模型支持视觉**（多模态）。纯文本模型只会看到"（图片）"。
- 图片存 `SCCORE_MEDIA` 指向的卷，默认 `media/`。和表情一样，要在卷里。
- 单张上限 6MiB，一次最多 2 张。

## 七、`/api/qq/status` 每个字段

```json
{
  "enabled": true,          // 配置完整、准备跑
  "problem": "",            // 非空 = 不跑，这句话就是原因
  "running": true,          // 线程起来了
  "connected": true,        // WebSocket 连着 NapCat
  "groups": ["123456"],     // 在哪些群
  "private": true,
  "ambient": true,          // 插话开着
  "ambient_today": 3,       // 今天已经插过几次
  "ambient_daily": 10,      // 今天最多几次（所有群合计）
  "people": 9,              // 认识多少人（说过话的）
  "turns": 42,              // 一共答了多少轮
  "sent": 40, "failed": 4,  // 发出去 / 发失败
  "last_error": "",         // 最近一次错误
  "events": 120,            // 收到多少个 OneBot 事件（不涨就是线断了）
  "stickers": 34,           // 表情张数
  "ladder": [ ... ],        // 实际解析到的熟稔度阶梯
  "loving": false,          // 恋爱标志
  "love_ping": true,        // 会主动发消息
  "generation": 3           // 人设重载次数（改文件后 `/重载` 会 +1）
}
```

## 八、清掉重来

只删 QQ 的数据，不动网页版的对话：

```sql
-- 在数据卷里的库上执行（sqlite3 data/scbot.db）
DROP TABLE IF EXISTS qq_identities;   -- 认识的 QQ 号、说过几次话、恋爱标志
DROP TABLE IF EXISTS qq_seen;         -- 群里见过谁、叫什么
DROP TABLE IF EXISTS qq_outbox;       -- 发送队列
DROP TABLE IF EXISTS qq_digest;       -- 记忆写到哪一条了
DROP TABLE IF EXISTS qq_stickers;     -- 表情包
DROP TABLE IF EXISTS qq_flags;        -- 静音等开关
```

`affinity` / `affinity_scenes` 是**内核的**好感度表（网页端也用），不要为了"清 QQ"删它们：
要清 QQ 那两场的分数，只删对应行：

```sql
DELETE FROM affinity_scenes WHERE surface IN ('group', 'dm');
```

重启后这些表会自动重建。

想连记忆文件一起清：

```bash
rm characters/memory/*.md
```

（`qq_digest` 表里的水位也要一起删，否则它认为"已经写过了"——所以上面那个 `DROP` 要一起做。）
