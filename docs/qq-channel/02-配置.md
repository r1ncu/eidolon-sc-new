# 02 · 配置

所有配置都从环境变量读，写在内核的 `.env` 里。完整模板：`templates/env.qq.example`。

**只有五行是必须的**，其余先不写也能跑：

```ini
QQ_ENABLED=1
QQ_SELF_ID=机器人QQ号
QQ_CHARACTER=角色ID
QQ_GROUP_IDS=群号          # 或者 QQ_PRIVATE=1，两者至少一个
QQ_ONEBOT_WS=ws://127.0.0.1:3001
```

改完 `.env` 必须重启进程（`systemctl restart` / `docker compose up -d`）。
只有**角色文件**（人设、world、stage、refusals）能热更新——那些不是环境变量。

---

## 一、连接

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_ENABLED` | `0` | 总开关。不设或 `0` 时整个通道不启动，`/api/qq/status` 会说明原因 |
| `QQ_SELF_ID` | 空 | **必填**。机器人自己的 QQ 号。用来过滤自己发的消息、判断有没有被 @ |
| `QQ_CHARACTER` | 空 | **必填**。用哪位角色的人格：`characters/characters.toml` 里的 id |
| `QQ_ONEBOT_WS` | `ws://127.0.0.1:3001` | NapCat 的 WebSocket 地址。容器里通常是 `ws://napcat:3001` |
| `QQ_ONEBOT_TOKEN` | 空 | NapCat 里设的 access token；没设就留空 |

启动时会做一次校验，缺什么就说什么：

```
QQ 通道没有启动：QQ_CHARACTER 是空的（不知道用哪位角色的人格去说话）
```

不猜角色是故意的：猜错不会报错，只会让她用别人的口吻说话。

## 二、待在哪儿

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_GROUP_IDS` | 空 | 群号，逗号分隔（`123,456`）。**是群号不是群名** |
| `QQ_PRIVATE` | `0` | 私聊总开关 |
| `QQ_PRIVATE_IDS` | 空 | 能私聊的 QQ 号。留空则沿用 `QQ_OWNER_IDS` |
| `QQ_OWNER_IDS` | 空 | "主人"：群里有专属语气、私聊里能进亲密关系、能收到她主动发的消息 |
| `QQ_IGNORE_IDS` | 空 | 完全不理会的人（别的机器人、刷屏的） |

私聊是白名单制。**不要设成"谁加都能聊"**：私聊用的那套语气是给特定的人写的，
对陌生人用会显得很奇怪，而且第一个找上来的通常是广告。

## 三、说话

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_MERGE_SECONDS` | `1.2` | 同一个人连发几条，合并成一次回答的窗口 |
| `QQ_MEMBER_COOLDOWN` | `20` | 同一个群友说完之后，她多少秒内不再接他的话。**主人不受这条限制**：它防的是一个群友霸着场，而他连发两句是两句正经话 |
| `QQ_CALLED` | `1` | 群里提到她时怎么办：`@ 她`、或者消息里**叫了她的名字**（名字表在 `<id>-stage.toml` 的 `names.mentions`）。开着 = **@ 一定回**（直接叫到就是叫她，不花判断）；**叫名字**才由她结合上下文判断要不要接，不回也记账。`0` = 回到旧行为（被 @ 就回、只听见那一句，叫名字不算） |
| `QQ_GROUP_CONCURRENCY` | `2` | 同时跑几个对话。机器弱、模型慢就调小 |
| `QQ_TURN_TIMEOUT` | `180` | 一轮对话最多等多少秒。超了就当这一轮失败（说一句"没说出来"），并发位让出来——没有上限时，卡住的请求会一直占着位置，看起来就是"有时候不回，过一阵又好了" |
| `QQ_WORLD` | `1` | 要不要把"对面是谁"的规则放进提示词 |
| `QQ_META` | `1` | 要不要在聊到作品/活动时注入 `world/meta.md` |
| `QQ_BRACKET` | `1` | 允不允许她"在句尾括号里补一句心里话" |
| `QQ_VOICE` | `0` | 发语音（需要语音插件与 `FISH_AUDIO_API_KEY`） |
| `QQ_COMMANDS` | `owner` | 谁能用 `/重开 /好感 /静音`：`owner` = 只有主人；其它值 = 群里谁都能用 |
| `QQ_SHARED_COMMANDS` | `表情` | `QQ_COMMANDS=owner` 时，额外允许群友用哪几个（逗号分隔）。能开的名字只有 `表情` 和 `好感`——它们读的都是问的人自己的东西；`/重载` `/静音` `/阶段` `/表情标` 写进来也不开。同一人 15 秒只能问一次 |

### 自己插话（`QQ_AMBIENT_*`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_AMBIENT` | `0` | 插话总开关。关掉 = 只在被 @ 时说话 |
| `QQ_HOLIDAYS` / `QQ_WORKDAYS` | 空 | 休息日 / 上班日的日历纠正（`YYYY-MM-DD`）。工作日 23–9、休息日 2–9 不主动开口 |
| `QQ_AMBIENT_DAILY` | `10` | **每个群**一天最多主动插话几次（各群各一份，`0` = 不限）。管的是频率 |
| `QQ_AMBIENT_GAP` | `240` | 两次插话之间至少隔多少秒 |
| `QQ_AMBIENT_CHECK` | `300` | 两次「要不要插话」的判断之间至少隔多少秒。判断是一次模型请求，这个只管成本 |
| `QQ_AMBIENT_HEARD` | `8` | 给她看的最近几行群聊 |
| `QQ_AMBIENT_P` | `1` | 每条群消息有多大比例会被"认真看一眼"。成本闸，不决定说不说；调到 0.1 以下会让消息少的群抽不到 |
| `QQ_AMBIENT_STICKER_P` | `0.3` | 插话里有多大比例只发一张表情、不说话 |
| `QQ_AMBIENT_OWN_P` | `0.35` | 插话里有多大比例**不是在接话**，而是说一句自己的事 |
| `QQ_AMBIENT_IDLE` | `0` | 群里安静多少分钟后她可能自己开口（分钟，0 = 关）。只在 9:00–23:00 |

**一天十次是次数，不是概率；而且是每个群各自十次**（热闹的群吃不掉安静的群的额度）。 以前 `P` 是"她要不要说话"的骰子，群里一分钟十条消息就是一天
一百多次。现在频率由 `DAILY` 封顶、`GAP` 摊开，`P` 和 `CHECK` 只管成本（每次判断都是一次模型请求）。

### 插不插，是读出来的，不是掷出来的

她不被叫到时，会读最近 `HEARD` 行，然后回答两个问题：**有没有她想接的话**、**要接哪一句**。
依据是 `characters/world/<角色ID>-interests.md`（见 `04-自定义角色.md`），不是环境变量——
换一个角色，她该接的话头也跟着换。

所以：

- 群里在聊她完全不懂的东西 → 她一句都不说，`DAILY` 一次也不花。
- 有人在问「新曲 MV 看了吗」，三个人回答完，她仍然可以回最开始那个问题。
- 模型挂了或答得看不懂 → 当作「不说」。主动开口这件事不能靠猜。

`QQ_AMBIENT_OWN_P` 是最影响"像不像人"的一个：

- `0` —— 每次插话都在接别人某一句话。热闹，但像个应声虫。
- `0.35` —— 三次里有一次是她自己的念头，不回应任何人。
- `1` —— 从不接话，只自说自话。

### 作息（`QQ_SLEEP`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_SLEEP` | `1` | 她有没有作息。`0` = 整套关掉：她什么时候都在 |

关掉的不是"晚上不闭嘴"这一件，是**整套作息**：

- `resting()` 一律回答 False —— 主动插话、主动私聊、深夜轮数上限都不再受钟点约束；
- 不再掷"今晚熬几小时"的骰子，不写 `sleep:<角色>:<日期>` 那本账；
- 深夜被 @ 不再加"被吵醒"那一段，也不再有几轮之后自己去睡这件事。

**只想挪钟点就别关它**——九点睡改成十一点睡是角色数据，写在
`characters/packs/<角色ID>/voice/night.toml` 里（见 `04-自定义角色.md`）。
同一个文件里写 `enabled = false` 可以只让**这一个角色**没有作息，别的照睡。
`.env` 的 `QQ_SLEEP=0` 是整个部署都不睡，比它优先。

作息开着的时候，睡着的时段里被 @ 她照样回（一条 @ 被吞掉比被吵醒更像坏掉），
只是语气不一样、而且聊几轮之后她会自己去睡——那几轮和那几句也是 `night.toml` 里的。

### 表情

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_STICKERS` | `1` | 收录群里发的表情，之后可以再用 |
| `QQ_STICKERS_PUBLIC` | `1` | 群友也能发 `/表情` 讨一张（每人 15 秒一次） |
| `QQ_STICKER_DIR` | 空 | 表情存哪儿。留空 = 数据卷里的 `media/stickers` |
| `QQ_MONDAY_HOUR` | `9` | 每周一几点发那张"上班"表情（0–23），`-1` 关掉 |
| `QQ_MONDAY_GROUPS` | 空 | 这张表情发到哪几个群（逗号分隔）。留空 = 所有群。要求往往来自某一个群 |

## 四、关系（只对私聊里的主人生效）

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_OWNER_STAGE` | `close` | 主人在群里从哪一档开始：`new`/`familiar`/`close`/`inner`，空 = 从最低档 |
| `QQ_OWNER_AFFINITY` | `0` | 好感度地板（0–100，0 = 不管）。防止判官把她一路扣成"疏远"。派生形态（`derived_from`）也归本体，所以这条照样管她 |
| `QQ_OWNER_LOVE` | `0` | 进入"恋爱"的好感门槛（0 = 不启用）。建议 95 |
| `QQ_OWNER_LOVE_TURNS` | `20` | 还需要说过这么多次话。两个条件缺一不可 |
| `QQ_OWNER_LOVE_FLOOR` | `90` | 恋爱之后的好感地板 |
| `QQ_OWNER_LOVE_PING` | `1` | 私聊开着时她会不会不定时先发消息。**跟恋爱无关**：恋爱只改这条消息说什么；设 `0` = 只回话、不主动 |
| `QQ_OWNER_LOVE_PING_MIN` | `60` | 两条主动消息之间的最短间隔（分钟） |
| `QQ_OWNER_LOVE_PING_MAX` | `150` | 最长间隔（分钟）。9:00–23:00 之外不计时：这段时间她会直接等到早上，不白等一个间隔 |

下一次的时间点存在库里（`qq_flags` 的 `love:next`），不是只存在那个任务里：重启等的是同一个
时刻，停机期间到点的会在活过来之后补上，刚发过的 20 分钟内不会因为重启再发一条。日志里有
`下一次主动私聊 21:35（还有 87 分钟）`，可以据此判断它到底有没有在跑。

"恋爱"是一个**标志**，不是分数区间：一旦进入，掉分、重置、重启都不会自动退出——
只有你手动改库才会。这是故意的：关系不是每天重新算一次的东西。

群聊和私聊的好感度是**两张表**（`affinity_scenes`）。群里几十个人闹出来的分数，
不会影响你们两个人之间。所以 `QQ_OWNER_AFFINITY` 也只在私聊里抬地板。

### 派生角色：另一个形态，同一个人

在 `characters.toml` 里写 `derived_from = "luna"`，她就是那个人的**另一个形态**
（幼年版、if 线、学生版……）。同一套机制，但这些东西是分开的：

- **好感不是分开的**（2026-11-06 起）：一行记在**本体**名下，本体/幼年/if 线共用。
  「私聊的她」和「群里的她」仍然是两本账（表按 `surface` 分），换形态不换那一行，
  `QQ_OWNER_AFFINITY` 那条地板也就照样管她。历史数据用
  `python tools/fold_affinity.py --db <库> --characters <角色目录> --apply` 折平
  （干跑不加 `--apply`）；
- **睡眠账本**按她自己的 id 记（`sleep:<角色>:<日期>`、`rest:<角色>:…`）——
  成年那一版今晚睡了，不代表幼年那一版也闭嘴；
- **记忆**写在 `characters/memory/<她自己的 id>/` 下（但 `derived_from` 之间互相认得，
  另一条人生的记忆会当成「梦」，不是「听别人说的」）；
- **tease（夹子）、tiers（档位声线）一件都不继承**。`tease` 是冬優子独有；
  `tiers` 现在是**每个本体角色都可以有**的一份（按好感档位换语气），但派生形态
  不借本体那一份——她要么自己写，要么就用群语域的中性兜底，检查脚本会拦住复制过去的做法。

做幼年版的标准动作只有三件：`derived_from` 写清楚、`voice/night.toml` 写她自己的
钟点和被叫醒的话、包里**不放** `tease.toml` / `tiers.toml`。`tools/check_packs.py`
会检查这三条。

## 五、记忆文件

| 变量 | 默认 | 说明 |
|---|---|---|
| `QQ_DIGEST` | `1` | 把聊天写成 `characters/memory/*.md` |
| `QQ_DIGEST_DM_DAYS` | `3` | 私聊多久重写一次（天） |
| `QQ_DIGEST_GROUP_DAYS` | `7` | 一个群多久重写一次（天） |
| `QQ_DIGEST_PROMPT` | `1` | 写好的记忆进不进提示词。进，她才真的记得 |

写出来的是**整份重写**，不是追加：新的盖掉旧的，文件里只有"现在还记得的事"。
少于 4 条新消息不写（省一次模型调用），第一次启动会立刻写一份。

文件在 `characters/memory/` 下，宿主机上直接能看：

```
characters/memory/dm-<QQ号>.md
characters/memory/group-<群号>.md
```

容器部署时这个目录要可写。典型错误见 [05-排错](05-排错.md) 的"记忆文件没生成"。
