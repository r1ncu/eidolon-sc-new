# 04 · 自定义角色

这个插件里**没有一个字属于某个特定角色**。她是谁、怎么说话、被问到什么会绕开，全部由
`characters/` 下的文件决定。换一个角色 = 换一组文件 + 改一行 `QQ_CHARACTER`，不动代码。

## 角色是七份文件

| 文件 | 位置 | 管什么 | 不写会怎样 |
|---|---|---|---|
| **人设** | `characters/sheets/<id>.md` | 她是谁：经历、性格、说话方式、在意的东西 | 她会用世界知识现编，说着说着就变成通用助手 |
| **资料** | `characters/facts/<id>.md` | 具体事实：人物关系、作品、口味、发生过什么 | 少细节。不会崩，但问深了会答不出来 |
| **群聊规则** | `characters/world/<id>-qq.md` | 群里这一场戏：对面是谁、能接多少、几档熟稔度 | 用中性兜底，像个有礼貌的陌生人 |
| **私聊规则** | `characters/world/<id>-dm.md` | 一对一这一场戏：不对外的那一面 | 同上 |
| **措辞表** | `characters/world/<id>-stage.toml` | 怎么称呼对面、记忆里署什么名、听不懂时说什么 | 中性默认，不带名字 |
| **拒绝台词** | `characters/world/<id>-refusals.toml` | 限额用完、被静音、模型挂了的时候说什么 | 中性默认（礼貌、无个性） |
| **插话清单** | `characters/world/<id>-interests.md` | 没人叫她时，什么话题她会自己开口、什么装看不见 | 中性默认（什么都接一点），她会显得没有偏好 |

`<id>` 是你给这个角色的标识：小写字母、数字、`-`、`_`，例如 `amane`。它同时是
`characters.toml` 里的 `id`、文件名的一部分、和 `.env` 里 `QQ_CHARACTER` 的值——**三处必须一致**。

## 第 1 步：登记

`characters/characters.toml` 里加一段：

```toml
[[characters]]
id = "amane"
name = "天音"                       # 显示名（可以用日文）
name_zh = "天音"                    # 搜索用的中文译名（可选）
name_romaji = "Amane"               # 搜索用的罗马字（可选）
intro = "一句话介绍，角色选择页会显示。"
sheet = "sheets/amane.md"
color = "#7a9bd4"                   # 印象色，界面上的基调
# facts = "facts/amane.md"          # 有资料时再打开这行
```

只要 `id` 和 `sheet` 是必须的。其余缺了就是没有对应功能（比如没有 `voice_id` 就不发语音）。

## 第 2 步：人设

`characters/sheets/amane.md`。这是最大的一份，也是最重要的一份——**它是人格，不是设定集**。

结构建议（不必照抄标题，但顺序有效）：

```md
# 人设：天音

你是天音。……（第一句就定死"你是谁"，用第二人称写）

## 说话方式
不写"温柔"，写她实际会说的句子：
- 不说「我知道了」，说「嗯，好」。
- 被夸的时候会先否认一句，再偷偷高兴。
- 生气的时候句子变短，不解释。

## 你在意的事 / 你的过去
（具体的事，不是形容词。她需要"记得"东西，才不会每轮都像第一次见面。）

## 不要做的事
（这一节要短。否定句对模型很弱，只写最不能破的两三条。）
```

三条经验：

1. **给样本，不要给形容词。** "毒舌"模型会理解成随机损人；写三句她损人的原话，它才抓得住密度。
2. **第二人称写。** "你是……""你会……"，不要写"天音是一个……"——后者读起来像维基条目。
3. **人设里不要写场景规则。** "在群里要客气"属于 `-qq.md`。写进人设会让私聊也变客气。

## 第 3 步：群聊规则

复制 `templates/world/example-qq.md` → `characters/world/<id>-qq.md`，然后重写。

这个文件每轮都会进提示词，所以它比人设更"贴身"。三件事必须说清楚：

- **【场景】** 这是什么房间（群里？几十人？有镜头吗？）
- **【对面】/{距离}** 这两段不用你写——它们是占位符，运行时会填。你要保证它们**在文件里**。
- **【阶段 xxx｜N】** 熟稔度阶梯：从第 N 次回答开始，语气变成什么。放在文件最后。

四个占位符，原样保留：

| 占位符 | 会被填成 |
|---|---|
| `{{addressee}}` | 对面是谁（主人 / 群里其他人 / 没人叫你 / 你自己想说） |
| `{{distance}}` | 能接多少（只听见叫你的这句 / 刚才几行看见了 / 不接话） |
| `{{time}}` | 现在是几点、星期几 |
| （没有第四个） | |

"对面是谁"那四段文字本身在 `-stage.toml` 里（见第 5 步），不在这个文件里。

## 第 4 步：私聊规则

复制 `templates/world/example-dm.md` → `characters/world/<id>-dm.md`。

私聊和群聊不是同一场戏的两种音量。**最容易写错的地方**是把它写成"群里那套 + 更亲近"，
结果她在私聊里还是在营业。判断标准：把两份文件并排读，如果私聊那份只是语气软了一点，
就还没写完——私聊里应该有一些**群里绝对不会说**的话。

两段特殊结构：

- **【场景】** 和 **【恋爱】** 进的是"人设"槽（不是每轮规则），因为它们必须在人设之前被读到。
- **【恋爱】** 只在进入恋爱状态之后才被读；没谈恋爱时它在提示词之外。不想要恋爱线就删掉这段。

## 第 5 步：措辞表

复制 `templates/world/example-stage.toml` → `characters/world/<id>-stage.toml`。

里面是七八段文字，每段对应一个场合：

| 键 | 什么时候用 |
|---|---|
| `addressee.owner` / `.stranger` / `.crowd` / `.alone` | 群聊里"对面是谁"的四种情况 |
| `distance.called` / `.ambient` / `.own` | "能接多少"的三种情况 |
| `fallback.group` / `.dm` | 两个规则文件都不存在时的兜底模板 |
| `names.self` / `names.owner` | 记忆文件里的署名、日志里的称呼 |
| `names.mentions` | 群里说到哪些名字算「提到了她」（见下） |
| `replies.unknown` | 指令没听懂时说什么 |

`names.self` 值得单独说：记忆文件每一行是 `<自称>：<她说过的话>`，`names.self` 就是那个自称。
留空就写"自己："——干净，但不像她。**填一个她自己会用的短称**。

`names.mentions` 是「不用 @，消息里出现这些名字就算叫她」。一条字符串，用顿号/逗号/斜杠分隔：
`mentions = "ふゆ、冬優子、黛冬优子"`。只收**不会被日常对话带出来**的形式——两个字的小名
（「冬优」）不要收，「严冬优雅」这种词里就有它，误叫一次比漏叫十次难看。留空 = 只有 @ 算数。

## 第 6 步：拒绝台词

复制 `templates/world/example-refusals.toml` → `characters/world/<id>-refusals.toml`。

这些是"这一轮根本没发生"的时候说的话：限额用完、冷却中、照片没存下来、模型挂了。
群里有五十个人会读到，所以必须像她说的，而不是像错误码。

两个占位符：`{wait}` → 「20 秒后」；`{wait_raw}` → 「20 秒」（日语等动词在后的语言用这个）。
一行里不放也可以，那就是不提还要等多久。

## 第 7 步：插话清单（她会不会自己开口）

复制 `templates/world/example-interests.md` → `characters/world/<id>-interests.md`。

这份文件只回答一件事：**没人叫她的时候，她看见什么会想说话**。她不是被叫到的，所以
这段话不是"她是谁"（那在 `sheets/`），而是"什么能让她开口"：

```markdown
## 一定会接
- 工作本身：练习、收录、LIVE、曲子。她对这些有意见，而且说得具体。
- 吃和睡：今天吃了什么、几点睡的。她会管人，也愿意被管。

## 不接
- 看不懂的缩写和梗、别人的私事、吵起来的架。
- 点名要别人回答的问题——那是问那个人的，不是问她。
```

写的时候有两点值得记住：

- **"不接"比"会接"重要**。群里大部分话都与她无关，一份只写「她什么都感兴趣」的清单会让
  她变成一个见缝插针的号。
- 写得**具体**。`「吃的」` 不如 `「今天吃了什么、几点睡的、有没有好好吃饭」`——判断的人拿到
  的是原文，不是你的意图。

这份文件同时决定她**接哪一句**：她可能回三行前那个问题，而不是刚发出来的那句抱怨。

没有这个文件也能跑，用的是中性默认（接得上就接，看不懂就不接）。

## 第 8 步：打开

```ini
QQ_CHARACTER=amane
```

重启内核。日志里应该出现：

```
QQ 通道已启动：群 123456 / 角色 amane / ws://127.0.0.1:3001
```

## 最小可用版本

只想先看看效果？**两份文件就够**：

```
characters/sheets/amane.md
characters/world/amane-qq.md
```

`-dm.md` 没有时私聊会用 `-qq.md` 的兜底模板（中性）；`-stage.toml` 没有时用中性措辞；
`-interests.md` 没有时她什么话题都接一点，显得没有偏好。它会跑，只是没那么像。

## 判断文件有没有生效

改完不用重启（角色文件是热读的）：

```
/重载                 # 在群里或私聊发这条（主人）
curl -X POST localhost:8100/api/qq/reload
```

然后看 `GET /api/qq/status` 的 `ladder` 字段——那是它**实际解析到**的阶段：

```json
{"ladder": [{"stage": "new", "from": 0, "chars": 210},
            {"stage": "close", "from": 15, "chars": 180}]}
```

`ladder` 跟你文件里写的不一样，说明【阶段】标题的写法不对：必须是
`【阶段 名字｜数字】`，全角竖线或半角 `|` 都行，但`【】`和空格不能少。

## 常见写错的地方

| 现象 | 原因 |
|---|---|
| 她完全不说话 | `QQ_CHARACTER` 和文件名不一致 → 日志 `QQ 通道没有启动` |
| 说话像通用助手 | 缺 `-qq.md`，或者里面只有形容词没有句子 |
| 群里太客气、私聊也客气 | 私聊规则写成了"群里 + 更亲近"，没有写出群里不会说的话 |
| 每轮都在重复同一句开场 | 人设里没有"她记得什么"；把 `facts` 打开，或者把记忆文件打开（`QQ_DIGEST_PROMPT=1`） |
| 阶段永远是第一档 | 阶段门槛数字写反了，或者【阶段】段落不在文件最后 |
| 记忆文件里没有名字 | `-stage.toml` 的 `[names] self` 空着 |
