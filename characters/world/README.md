# world/ —— 她的语气、话题和禁区

这里的文件按 `<角色id>-<用途>.<后缀>` 命名，缺哪个就是没有那一层，不会报错。
全部是**给模型读的数据**，代码只负责挑哪些进提示词。

## 文件清单

| 文件 | 管什么 | 什么时候进提示词 |
|---|---|---|
| `<id>-qq.md` | 群聊里的她：语气、距离档、称呼、群里的规矩 | 群聊每一轮 |
| `<id>-dm.md` | 私聊里的她：语气、【恋爱】【暧昧】【等答复】三段 | 私聊每一轮 |
| `<id>-interests.md` | 她接得上什么话头、什么不接 | 判断「要不要插话」时 |
| `<id>-stories.toml` | 话题 → 剧情片段的表 | 命中关键词才注入（≤3 段） |
| `<id>-stage.toml` | 熟络档的阈值、每档怎么叫人 | 每轮（群聊） |
| `<id>-refusals.toml` | 答不上来时的固定话术 | 只在被拦住时发 |
| `<id>-idols.toml` | 她认识的同行（名字、别名、亲疏） | 群聊提到这些名字时 |
| `<id>-qzone.md` | 发 QQ 空间时的写作口径 | 写说说时 |
| `meta.md` / `office.md` / `idols/` | 可选的公共资料（作品、事务所、别人） | 命中话题时 |

## 一条容易踩的线：什么必须中文

QQ 通道**只发中文字幕**。模型的回复是「`<ja>` 日语原文 + `<zh>` 中文字幕」，只发后者。
所以：

- **`<id>-refusals.toml` 里每一句都必须写中文**——那边的字符串是直接进气泡的，
  写日语就等于让一个看不懂日语的人读日语。`{wait}` 会被替换成「20 秒后」。
- **人设文件（`-qq.md` / `-dm.md` / `-qzone.md`）里可以写日语**：那是给模型看的语气样本，
  它照着写 `<ja>`，字幕另出。写中文示例也行，模型会把中文写进 `<ja>`，字幕再翻回去。
- 提示词里的人名、自称（比如「ふゆ」）用原文，不要翻译——那是她怎么叫自己。

网页端是双语的（两段都显示），不受这条影响。

## 骨架

`-qq.md` —— 群聊，最重要的是「距离」怎么写：

```markdown
【场景】QQ 群，一群不太熟的人。你在这里不是对谁都热络。
【称呼】叫我「ふゆ」的人不多。
【距离·语气】第一条：越陌生越客气，句子越短。……
【字幕】中文是字幕，不是另一个角色：照日语原话说，短句。
```

`-dm.md` —— 私聊，三段是互斥的，代码按关系状态选一段注入：

```markdown
【场景】私聊，只有你们两个。
【恋爱】……（已经在谈恋爱时的语气）
【暧昧】……（有点什么，但谁都没说破）
【等答复】……（她说了，他还没答）
【语域】……
```

`-refusals.toml` —— 两个场景各七句，全部中文：

```toml
[group]
too_long = "（……太长了。一次说短一点行不行？）"
failed   = "（……抱歉，没听清。再说一次行不行？）"

[direct]
too_long = "……太长了。说短点。"
failed   = "……没听清。再说一次。"
```

`-stories.toml` —— 话题命中才注入，所以关键词要具体：

```toml
[[topic]]
name = "第一次上台"
words = ["第一次上台", "初舞台", "第一次 live"]
from = [{ file = "01-成长/成长.md", scene = "第一次上台" }]
```

`from` 里的 `file` 相对 `characters/facts/<id>-stories/`，`scene` 是那个 md 里 `##` 的标题。

## 不要放进来

这里最容易夹带原作内容：剧情台词、官方设定、别人的角色关系。写自己的角色时没问题，
**把别人的角色写进来再提交，就是在分发别人的作品**。
