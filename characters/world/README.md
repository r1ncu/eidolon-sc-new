# world/ —— **共享层**：这个作品和这间事务所

这里只剩「谁都知道的事」：作品叫什么、事务所是哪个、名单上有谁。一份，所有角色共用。

**角色的东西不在这里。** 她的语气、称呼、档位、资料、剧情、特别设定，全部在
`characters/packs/<id>/`（见 `characters/README.md`）。以前是 `world/<id>-qq.md` 这种
扁平名，现在只有共享层留在这个目录；旧路径仍然读得到（解析顺序是先 pack 再旧路径），
但新写的东西不要再放进来。

## 文件清单

| 文件 | 管什么 | 什么时候进提示词 |
|---|---|---|
| `work.md` | 作品的客观事实：企划、活动、制作侧 | 提到作品本身的话题词时 |
| `office.md` | 名单：谁、在哪个组合、一句话 | 每轮（群聊与私聊都在） |
| `meta.md` | 事务所与作品周边的细节（可选） | 命中话题时 |
| `idols/<id>.md` | 某位同行的详细资料 | 群聊提到这个名字时 |

这四个都是**事实**，没有第一人称、没有评价。她怎么称呼这些人、怎么看这个作品，写在
`packs/<id>/view.md` 和 `packs/<id>/world.md` 里——那是她的看法，一角色一份。

## 一条容易踩的线：什么必须中文

QQ 通道**只发中文字幕**。模型的回复是「`<ja>` 日语原文 + `<zh>` 中文字幕」，只发后者。
所以：

- **`packs/<id>/voice/refusals.toml` 里每一句都必须写中文**——那边的字符串是直接进气泡的，
  写日语就等于让一个看不懂日语的人读日语。`{wait}` 会被替换成「20 秒后」。
- **人设文件（`voice/qq.md` / `voice/dm.md` / `voice/qzone.md`）里可以写日语**：那是给模型
  看的语气样本，它照着写 `<ja>`，字幕另出。写中文示例也行，模型会把中文写进 `<ja>`，
  字幕再翻回去。
- 提示词里的人名、自称（比如「ふゆ」）用原文，不要翻译——那是她怎么叫自己。

网页端是双语的（两段都显示），不受这条影响。

## 结构的两个样板

`packs/<id>/voice/qq.md` —— 群聊，最重要的是「距离」怎么写：

```markdown
【场景】QQ 群，一群不太熟的人。你在这里不是对谁都热络。
【称呼】叫我「ふゆ」的人不多。
【距离·语气】第一条：越陌生越客气，句子越短。……
【字幕】中文是字幕，不是另一个角色：照日语原话说，短句。
{{extra}}
```

`{{extra}}` 是「她自己某条特别设定」落地的位置（见 `voice/tease.md`），没有那份文件时
这一行会被收掉，不留空行。

`packs/<id>/voice/dm.md` —— 私聊，三段是互斥的，代码按关系状态选一段注入：

```markdown
【场景】私聊，只有你们两个。
【恋爱】……（已经在谈恋爱时的语气）
【暧昧】……（有点什么，但谁都没说破）
【等答复】……（她说了，他还没答）
【语域】……
```

## 不要放进来

这里最容易夹带原作内容：剧情台词、官方设定、别人的角色关系。写自己的角色时没问题，
**把别人的角色写进来再提交，就是在分发别人的作品**。
